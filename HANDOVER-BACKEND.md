# AIyachts — backend handover

Written for Alex, who is building the CMS behind this site.

The front end is a static site generated by `node build/build.mjs` from the data
in `build/site.mjs`. Everything the client asked to be editable already has a
shape in that file and a renderer that consumes it. This document is that shape,
written out as a content model, so the CMS can produce the same thing.

Read `README.md` first for how the generator works. This file only covers the
data.

## 2. Content model

Types below are the ones a CMS would use. "Front end" says which file consumes
the field, so a change can be traced.

### 2.1 Yacht

The core entity. 14 exist. Front end: `FLEET` in `build/site.mjs`,
rendered by `fleet.html` and `fleet/<slug>.html`.

| Field | Type | Req | Notes |
|---|---|---|---|
| `slug` | slug | ✅ | URL and image filename key. Never change it after launch — it is the page URL. |
| `name` | text | ✅ | e.g. `Bavaria 46 Cruiser` |
| `builder` | text | ✅ | e.g. `Bavaria Yachts` |
| `year` | text | ✅ | Model year, printed as given |
| `cat` | text | ✅ | Card label: `2 Cabins` … `5 Cabins`, `Catamaran` |
| `type` | select | ✅ | `Monohull` \| `Catamaran`. Drives the badge and the filter. |
| `cabins` `guests` `berths` `heads` | integer | ✅ | Printed in the card, the spec strip and the table |
| `tag` | text | ✅ | One-line hook, e.g. *The all-rounder* |
| `blurb` | textarea | ✅ | 2–4 sentences on the yacht page |
| `highlights` | repeater(text) | ✅ | 3 short lines, "What she is good at" |
| **`owner`** | select | ✅ | `own` → *Our Fleet*, `partner` → *Partners' Yachts*. All 14 are `partner` today. |
| **`photos`** | repeater | — | The gallery. See 2.2. Empty ⇒ the page shows the main photograph and an invitation to ask for more. |
| **`equipment`** | group of lists | — | See 2.3. Empty ⇒ the whole Equipment block is omitted. |
| `loa` `beam` `draft` `displacement` | text | — | Optional spec rows. Each one present adds a row; absent ones are simply not printed. |
| `engine` `fuel` `water` | text | — | Same |
| `mainsail` `headsail` | text | — | Same |

**Nothing is invented.** The spec table only ever prints fields that have a
value, which is why it is short today. That behaviour should be preserved — the
client would rather show eight rows than guess at twelve.

| Field | Type | Req | Notes |
|---|---|---|---|
| `slug` | slug | ✅ | Filename key, see §3 |

### 2.3 Equipment

Matches the example the client sent. An ordered map of group name → list of
items:

```
'Outdoor equipment'  → ['Bimini', 'Bathing ladder']
'Leisure activities' → ['Paddle board', 'Snorkelling equipment']
'Sails & rigging'    → ['Battened mainsail', 'Furling genoa']
```

Group names are free text so the client can add "Navigation", "Galley", "Safety"
without a code change. In a CMS this is a repeater of
`{ group_name, items[] }`.

## 3. Image contract

Every photograph is delivered as **four files** — two widths × two formats —
because the markup uses `<picture>` with a WebP source and a JPEG fallback:

```
<slug>-800.jpg   <slug>-800.webp
<slug>-1600.jpg  <slug>-1600.webp
```

| What | Directory |
|---|---|
| Gallery, hero and service photographs | `assets/gallery/` |
| Yacht card / hero photograph | `assets/fleet/<slug>.jpg` (single file, historic) |
| Yacht gallery frames | `assets/fleet/gallery/` |
| Brokerage listing frames | `assets/brokerage/` and `assets/brokerage/gallery/` |
| Portraits | `assets/team/` (`-400` and `-800`) |

`build/media.py` and `build/media-2026-09.py` show exactly how the derivatives
are made (Pillow, JPEG q82 progressive, WebP q80 method 6). **In WordPress this
is what `add_image_size()` plus a WebP plugin does** — the important part is that
both widths and both formats exist, and that `srcset` keeps offering them.

Photographs larger than the target width are downscaled; smaller ones are copied
at native size rather than upscaled.

## 4. Markup contracts the JavaScript depends on

`assets/js/site.js` is plain, dependency-free, and binds to these. If the CMS
templates change the markup, keep these hooks:

| Hook | Used by |
|---|---|
| `#fleetFilters .xg-chip[data-filter]` | Fleet size/type filter |
| `[data-fleet-grid]` on each category grid, `[data-fleet-empty]` on its note | Filtering across *Our Fleet* and *Partners' Yachts*; a category with no matches shows the note instead |
| `.yacht-card[data-cat]` | `catamaran` \| `small` \| `mid` \| `large` |
| `.xg-grid` + `.xg-tile` + `.xg-open` | Every gallery, including the per-yacht ones |
| `.xg-tile[data-full]`, `[data-full-webp]`, `[data-alt]`, `[data-title]`, `[data-video]`, `[data-poster]` | The full-screen viewer reads the large image straight off the tile |
| `[data-gallery-more]` inside `.gallery-more`, immediately after its grid | The *More photographs* button |
| `#xgLightbox`, `#xgStage`, `#xgCap`, `#xgCount` | The viewer itself. One per page. |
| `.reveal` / `.reveal-stagger` | Scroll-in animation; harmless if absent |

The four charter formats are native `<details>` / `<summary>` — no JavaScript,
so they work before the script loads and with it disabled.

## 5. Where the WordPress theme currently stands

`wp-theme/aiyachts/` is a **front-page-only** theme: `front-page.php` plus
`inc/front-page-parts.php` reproduce the home page, and `inc/acf-fields.php`
registers the ACF group that makes every block on it editable. The inner pages
are not yet templated — that is the work ahead.

Two things worth knowing before extending it:

1. **Every default lives in PHP, not in the database.** `aiy_get_field( 'x', 'a
   default' )` returns the ACF value if an editor has set one and the shipped
   copy otherwise, so the site renders correctly on a bare install. The three
   service cards changed in this update (`aiy_default_services()`), and their
   icons were added to `aiy_service_icon_paths()`. The three retired icons
   (`concierge`, `provisions`, `crew`) were deliberately kept so any card already
   saved in ACF keeps rendering.
2. **`assets/css/site.css` and `assets/js/site.js` under the theme are copies**
   of the ones at the repository root. They are byte-identical right now. If you
   edit one, copy it across, or the static preview and the WordPress site will
   drift apart.
